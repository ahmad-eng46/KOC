# Legacy Data Migration — CSV Drop Folder

The migrator (`pnpm migrate`) reads ten CSVs from this folder. Sample CSVs are checked in to let the migrator run dry against representative data; **replace each file with the real export from the legacy SQL Server `.mdf` before doing a confirmed run**.

## How to produce the real CSVs (Windows)

1. Attach the legacy `.mdf` in SQL Server Management Studio.
2. For each table below, run `SELECT * FROM <table>` and use **Save Results As → CSV** (UTF-8, comma delimiter, headers included).
3. Drop the resulting files into this folder, **using the exact filenames listed**.

## Expected files and columns

The migrator reads columns by header name (case-insensitive). Extra columns are ignored. Missing optional columns are treated as NULL.

| File | Required columns | Optional columns |
|---|---|---|
| `Customer_Table.csv` | `CustomerID`, `CustomerName` | `Phone`, `Address`, `OpeningBalance`, `City`, `CreatedDate` |
| `Product.csv` | `ProductID`, `ProductName` | `SKU`, `SalePrice`, `PurchasePrice`, `Stock`, `Unit` |
| `Stock_Table.csv` | `StockID`, `ProductID`, `Quantity` | `Date`, `Reference` |
| `Invoice_Table.csv` | `InvoiceID`, `InvoiceNo`, `CustomerID`, `InvoiceDate` | `SubTotal`, `Discount`, `Total`, `Paid`, `Notes` |
| `Invoice_Table1.csv` | `InvoiceID`, `ProductID`, `Qty`, `Rate` | `ID`, `Amount` |
| `Cash_Table.csv` | `CashID`, `CustomerID`, `Amount`, `PayDate` | `InvoiceID`, `PayMethod`, `Reference`, `Notes` |
| `Expense_Table.csv` | `ExpenseID`, `Category`, `Amount`, `ExpenseDate` | `Description` |
| `Investment_Table.csv` | `InvestmentID`, `InvestorName`, `Amount`, `InvestmentDate` | `Notes` |
| `Loan_Table.csv` | `LoanID`, `PartyName`, `Direction`, `Amount`, `LoanDate` | `DueDate`, `Status`, `Notes` |
| `Login.csv` | `Username`, `Role` | `UserID`, `Password`, `FullName`, `Email` |

## Conventions the migrator applies

- **Money:** legacy `DECIMAL` is treated as PKR. Multiplied by 100 and rounded to `BIGINT` paisa.
- **Dates:** legacy timestamps are read as Asia/Karachi local time and converted to UTC. Date-only fields (`InvoiceDate`, `PayDate`, etc.) are stored as `DATE` (no TZ conversion).
- **Business scoping:** legacy data has no concept of multiple businesses. The migrator auto-creates a single `Legacy` business and assigns every imported row to it.
- **Skipped tables:** `Ladger_Table` and `Profit_Table` are intentionally not imported — they are regenerated by triggers and the P&L calculator.
- **Login passwords:** legacy plaintext passwords are used as the seed password for `auth.admin.createUser`, which re-hashes them via bcrypt. Users with no `Password` get a generated temp password printed in the migration report.

## Running

```bash
pnpm migrate              # default: dry-run (no writes)
pnpm migrate --dry-run    # explicit dry-run
pnpm migrate --confirm    # actually write to Supabase
```

**Always run on a fresh Supabase project first.** Never run `--confirm` against production until a dry-run report has been reviewed.
